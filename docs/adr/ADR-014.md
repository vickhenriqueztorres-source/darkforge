# ADR-014: Estratégia de backup/PITR, Storage e restore testado com RPO/RTO explícitos

- **Status:** ACCEPTED
- **Data:** 2026-11-16
- **Requisitos relacionados:** `JOB-008`, RNF §13.2

## Contexto
Backup gerenciado do Postgres não inclui automaticamente objetos do Storage, e backup sem teste de restore não comprova recuperação.

## Decisão
Definir política explícita de backup combinando: (1) backup/PITR do Supabase conforme plano contratado, (2) export lógico versionado de dados e manifests, e (3) inventário/cópia versionada de objetos do Storage privado, com **teste de restore em projeto/ambiente isolado** antes de declarar o piloto pronto (`SP-09-T08`).

## Consequências e invariantes
- Metas iniciais de referência a validar no piloto: RPO lógico <= 24h (ou PITR conforme plano Supabase), RTO <= 2h para restore de workspace/projeto isolado.
- Toda migration destrutiva exige ponto de recuperação prévio e plano de rollback/roll-forward.
- `SP-09` só passa após restore comprovado de Postgres + RLS/memberships + Storage + manifests + embeddings/rebuild.
