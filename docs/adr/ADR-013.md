# ADR-013: Fila Postgres com lease, fencing, outbox/inbox e idempotência

- **Status:** ACCEPTED
- **Data:** 2026-11-16
- **Requisitos relacionados:** `JOB-001`..`JOB-006`, `PROD-002`..`PROD-004`

## Contexto
Workers locais podem fechar ou travar no meio de um job; Realtime/SSE pode perder pacotes; `SELECT` seguido de `UPDATE` via REST gera corrida entre workers.

## Decisão
Implementar fila no Supabase Postgres com reserva transacional via RPC/SQL `FOR UPDATE SKIP LOCKED`, `worker_id`, `lease_expires_at`, `heartbeat_at`, **`fencing_token` monotônico**, `idempotency_key` única por escopo e padrão **transactional outbox/inbox**.

## Consequências e invariantes
- Nenhum worker antigo com `fencing_token` obsoleto consegue commitar progresso, transição ou artifact.
- Nenhuma chamada externa (YouTube, IA, Storage) ocorre dentro de transação aberta do Postgres.
- Realtime/SSE com `last_event_id` é apenas notificação de progresso; o estado oficial sempre é reconstruível via `GET /api/v1/jobs/{id}`.
- Reconciler no boot e em intervalo periódico detecta leases expirados (`INTERRUPTED` -> `RECOVERABLE`) mesmo sem a UI aberta.
