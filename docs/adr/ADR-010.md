# ADR-010: pgvector como projeção reconstruível com revisão e RLS

- **Status:** ACCEPTED
- **Data:** 2026-11-16
- **Requisitos relacionados:** `KNOW-004`..`KNOW-008`

## Contexto
Misturar embeddings de modelos ou dimensões diferentes corrompe a busca vetorial, e um índice sem RLS ou filtros SQL vaza dados entre workspaces.

## Decisão
Armazenar vetores no **pgvector do Supabase Postgres** associados a `EmbeddingRevision` (`embedding_model`, `embedding_version`, `dimensions`, `status`). Tratar vetores como projeção derivada e reconstruível a partir de `KnowledgeSource`/`KnowledgeChunk`.

## Consequências e invariantes
- Troca de modelo cria uma nova `EmbeddingRevision` em estado `building`, executa rebuild isolado e só troca a revisão ativa após validação de cobertura/recall.
- Consultas híbridas (FTS + pgvector) aplicam filtro de `workspace_id`, canal, idioma, status (`L2`/`L3`) e direitos dentro da query/RPC SQL antes de retornar ao chamador.
