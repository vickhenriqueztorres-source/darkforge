# ADR-012: Supabase Storage privado para binários; filesystem local só para temporários/cache

- **Status:** ACCEPTED
- **Data:** 2026-11-16
- **Requisitos relacionados:** `JOB-008`, `PROD-005`, RNF §13.1, §13.2

## Contexto
Guardar vídeos, thumbnails ou raw payloads JSON em colunas Postgres `bytea`/base64 degrada banco e backup; guardar artifacts apenas no PC causa perda e divergência.

## Decisão
Usar **buckets privados no Supabase Storage** (`knowledge`, `references`, `exports`, `production`) com caminho `<workspace_id>/<opaque_id>`, tabela `storage_objects` (`sha256`, `size`, `content_type`, `status`), upload direto autorizado e signed URLs curtas. Filesystem local (`%LOCALAPPDATA%\DarkForge\`) guarda apenas cache e temporários descartáveis.

## Consequências e invariantes
- Ciclo obrigatório de upload: `uploading` -> `verifying` -> `ready` (ou `failed`/`orphaned`).
- Nenhum artifact ou upload é considerado concluído sem manifest e checksum validados.
- Reconciler periódico detecta objetos sem registro, registros sem objeto e uploads incompletos.
