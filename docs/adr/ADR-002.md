# ADR-002: Monólito modular Python e workers locais em vez de microserviços

- **Status:** ACCEPTED
- **Data:** 2026-11-16
- **Requisitos relacionados:** RNF §13.3, §13.5, Arquitetura §4, §5, §13

## Contexto
O uso inicial é de um operador em um PC administrando múltiplos canais em um workspace, com processamento local de vídeo, pesquisa e IA.

## Decisão
Adotar um **monólito modular em Python (FastAPI + `core/` + `adapters/`)** acompanhado de **processos workers locais separados** (`workers/`) e frontend `apps/web` (Next.js). Não adotar microserviços, Kafka, Redis ou Kubernetes no MVP.

## Consequências e invariantes
- Dependências unidirecionais: `apps/web` -> `apps/api` -> `core/` <- `adapters/`.
- `core/` não importa FastAPI, React, SDK do YouTube ou cliente HTTP de Supabase diretamente.
- Workers compartilham o mesmo domínio `core/` e o mesmo Job Manager Postgres.
